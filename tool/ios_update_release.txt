    schemaVersion: integer 1
    enabled: boolean true
    bundleId: exact com.colesmart.bitestar
    appleId: string "6792401678"
    version: actual PUBLIC Apple marketing version (1–3 numeric components)
    urgent: boolean false, unless the owner separately approves an urgent release
    issuedAt: current UTC ISO-8601 timestamp ending Z
    expiresAt: UTC ISO-8601 timestamp ending Z, after issuedAt, at most 7 days later
  Do not use CFBundleVersion/build numbers as the public target. Never activate

  Each new canonical public version has its own installation-level history.
  Publish only with separate owner authorization, then verify exact JSON, HTTPS,
  no-store headers and actual installed public builds before customer activation.

Disable a mistaken policy
  Set enabled=false and urgent=false, remove version/issuedAt/expiresAt, and
  separately authorize publishing that disabled file to the same URL. Existing
  history stays intact. Rechecks happen before opening the store and after return;
  no reminder is started on resume. An already visible dialog can use Update Now
  to recheck and dismiss a withdrawn/expired policy. No polling/background service.

Eligibility and limits
  Release Flutter builds on real iOS 16+ only. Native code requires a verified
  production AppTransaction, matching bundle, nonzero appID, matching installed
  build, and Apple's SHA-384 device-verification check. No receipt refresh prompt.
  TestFlight/sandbox, simulator/debug, unknown/unsupported channels fail open.
  Apple Storefront.current supplies the country, converted through Foundation's
  ISO aliases; phone language/location are never used as a storefront fallback.
  Public Apple lookup must match exact numeric ID, bundle and target version in
  that storefront, minimum OS and the exact device marketing token in supportedDevices.
  ios_store_devices.dart binds verified Xcode 26.5 modelIdentifier/name pairs to
  observed Apple public lookup tokens; matching is exact after the recorded
  whitespace/case normalization. No device-family inference. Most iPads, SE/XR
  variants, future devices and any other unmapped model remain usable without
  reminders until separately verified mappings are added/retested. See the table
  for actual coverage. This intentionally conservative compatibility coverage
  must be checked against intended release devices before activation.
  Missing/malformed/stale/disabled policy, mismatched identity, unavailable listing,
  unsupported hardware/OS, timeout/offline and failed handoff never consume history
  and never create a gate. HTTP redirects, non-JSON and oversized responses reject. Apple lookup's
  text/javascript MIME is accepted only on the exact HTTPS Apple lookup path
  and still must decode as JSON; the policy requires application/json.
  No customer/auth data, receipt, verification nonce or device identifier is sent
  to the policy endpoint; Apple lookup receives only public app ID and storefront.
  Apple lookup is public catalog evidence, not a per-customer installation promise.
  It cannot prove remaining disk space, Screen Time/MDM restrictions, account state
  at download time, phased-release behavior or every store-side outage. These need
  real distribution checks. Unknown compatibility is intentionally unsupported.
  App Store handoff opens Apple's HTTPS product universal link, with browser
  fallback disabled. A successful URL launch does
  not mean installation. On return, policy/store/version are checked again. A still
  eligible unchanged app retains the existing prompt with manual retry, no loop.
  A failed launch or recheck releases the gate. Real download/return restrictions
  cannot be qualified from a simulator, mock, or this unsigned build.
