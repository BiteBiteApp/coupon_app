## F6 bounded feasibility conclusion

A report-only prototype enumerated complete conservative recall in stable identity order, keeping only a native top-K heap and yielding after 64 SQL statements or 4 seconds. It reproduced the exhaustive native first-page results. For the selected geographic cases it enumerated 558–1,168 candidates in 5–10 SQL statements. For dense Finder it needed 202 statements, 25,842 candidates and 49,450,780 JSON bytes, spread across four bounded rounds before any useful result was proven; local elapsed time was 687 ms. That measurement predates the exact Finder fast path, which now achieves the serving result with far less transfer.

Complete enumeration can remove duplicated SQL rank logic and the lower-bound stopping proof, but it transfers all candidate volume and must still prove conservative recall, pin/checkpoint validity, exact native identity/authority, limits and latency across dense/fallback cases. It does not itself qualify another runtime. The reasonable decision for this run is to retain the corrected current strategy. Any replacement is **PRODUCT DECISION REQUIRED**, followed by separate qualification; no replacement was applied. This does not block the requested bounded feasibility study.

These results establish corrected, locally tested source on these fixtures. They do not establish hosted or production readiness, nationwide p95/p99, deployment approval, or billing.
