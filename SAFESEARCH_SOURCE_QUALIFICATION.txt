EXACT BYTES AND PUBLICATION
New bytes travel through the authenticated backend, capped at 5 MB, and are
saved by Admin Storage in the existing uploader-owned namespace with no
Firebase download token. The screened filename is reserved; clients cannot
create, replace, delete or enumerate these objects. Object metadata retains
the existing ownership proof and deletion namespace contract.

Private screening identity includes owner, Auth account creation time, exact
dish/restaurant/review/mode, MIME type, SHA-256 digest, and decimal generation
string. Duplicate bytes/context reuse the same record/object. Neither client
verdicts nor client URLs are accepted. Byte digest and generation are checked
before publication; replacement generations cannot inherit approval.

Storage Rules allow a screened tokenless GET only when two private/public
documents agree on approval, exact generation/path, and live nonremoved source.
Pending, held, rejected and failed objects have no public photo record, count,
primary selection or public DTO. Publication atomically writes source, private
decision and dish count/primary changes. Existing maintenance builds projections.
Concurrent missing-photo submissions can publish only one; the loser is held.
Deletion removes owned screening records/admission state through the existing
cleanup pipeline and owned bytes through the existing namespace/finalize logic.

Historical photos remain readable and are neither migrated nor rescanned.
Storage Rules in this commit are an explicit CUTOVER CANDIDATE: deploying them
alone would immediately stop old direct uploads. They have not been deployed.
The required=true server/Firestore gate blocks old callable/direct publication;
it must never be cleared as an outage workaround after activation.

CLASSIFICATION AND OWNER POLICY
Google REST images:annotate uses server ADC and SAFE_SEARCH_DETECTION only.
A small PhotoScreeningProvider interface supports deterministic test providers.
The real adapter refuses emulator/test environments and disables SDK retries.
Adult, violence, racy, medical and spoof likelihoods are validated and retained
privately. Invalid/missing responses and timeouts fail closed.

Candidate conservative-hold-v1: adult, violence and racy must each be
VERY_UNLIKELY or UNLIKELY for automatic approval. UNKNOWN/POSSIBLE/LIKELY/
VERY_LIKELY in any of those three means human review. Medical or spoof alone
does not block an otherwise acceptable food photo. No automatic-rejection
threshold is implemented. Admin can reject after inspection. Owner acceptance
of this candidate policy and review operations is required before activation.

Failed scan, completed scan, awaiting review, approved, rejected and already
removed remain distinct. Provider outages never authorize publication. A held
result is not rescanned merely because the user repeats the request.

COST, PAUSE AND RETENTION
No spending amount is selected. Private runtime photo_screening requires:
  required=true; enabled=true; policyVersion=conservative-hold-v1;
  retentionApproved=true; monthlyAllowance=<owner-approved positive integer>.
No such production document was created or changed. Missing/invalid settings
fail closed. The existing aggregation runtime must also be valid.

Atomic monthly reservedUnits is a conservative ceiling on admitted attempts,
not a provider invoice. Reservations are never refunded. A global four-slot
lease, four admissions/user/minute, two maximum attempts/object/context,
explicit retry and increasing backoff prevent automatic retry storms. The
callable has maxInstances=2, concurrency=2 and a 60-second timeout; the adapter
uses a 20-second request timeout. Gallery reads and triggers never call Vision.
After an unknown timeout a later intentional attempt may incur another charge;
exactly-once billing is not claimed. Refreshing a screen does not rescan.

Set enabled=false to stop new scans and in-flight automatic publication while
keeping required=true and the restrictive Rules. Deliberate Admin decisions
on existing held/failed photos remain available without a billable scan.
Allowance exhaustion stops new scan admission. Provider quotas and billing
alerts should complement application admission; alerts are not hard caps.

Official pricing checked October 16, 2026: first 1,000 units/month free;
SafeSearch-only $1.50/1,000 through five million, $0.60/1,000 above five million.

Functions usage can also cost money; the scan allowance does not cap those.
