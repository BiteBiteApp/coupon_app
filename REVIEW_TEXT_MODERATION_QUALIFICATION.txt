EXECUTION PATHS AND TRUST BOUNDARY
Dish-detail create/edit, Create & Rate existing dish, new dish, new restaurant,
and duplicate-match branches converge on BiteScoreService's existing
_createReviewAndRebuildAggregate -> saveReviewWithTrustedAggregate ->
saveCustomerBiteScoreReview. The historical direct Firestore fallback remains
unchanged when disabled; candidate Rules close it after required=true.
Rating-only and empty-field removal use the same trusted write and no provider.
The existing transactional aggregate calculation, contribution replacement,
review identity selection, Terms gate, posting restriction, deletion fence,
dish/restaurant/merge/milestone locks and review timestamp semantics remain.

The rating transaction reserves the current private text proposal and updates
its public textRevision pointer atomically. Proposed headline/notes never enter
dish_reviews until clean screening or authorized human approval. For a held edit,
old approved words stay; a submitted blank field removes that old field now.
A new review with held words has public numerical ratings and blank public words.
There is one rating contribution. Text decisions never alter rating fields,
aggregate values, review timestamps, photos, helpful votes or points.

One private record per review binds author UID, review/dish/restaurant IDs,
content digest, random version, trusted timestamps/deadline, status, requested
model/policy, returned model/request ID/category flags/scores and current Admin
decision. A separate per-user admission record has no words. Real API calls
would contain only neutral-separated headline and notes plus the model name.
No profile/account email, UID, account history, Auth token, restaurant owner
record, photo or billing metadata is attached to the provider payload. Users
may themselves type personal information in review text; this is not a reliable
PII detector or a promise of automatic redaction. Existing personal-information
Report Review reasons and evidence remain available.

Restaurant owners and client Admins can read dish_reviews under existing Rules;
therefore both private collections deny ALL client Firestore access. Author
status/drafts and Admin queue/decisions use authenticated callables. Author
responses are UID-bound; the Admin queue requires existing Admin authority,
replaces pages of at most 25 and clears private UI on account change. Its entry
is in the existing Review & Photo Reports area, separate from published reports.

Every completion rechecks exact current proposal/version/attempt, review identity,
account fence, posting restriction, current dish/restaurant identity/activity,
operation locks, expiration and existing published-review moderation flags.
Same-ID deletion/recreation, superseding edits, merges, account deletion and
stale Admin actions cannot revive old words. The existing review-write trigger
purges detached proposals without deleting a current replacement. Account
cleanup appends two collection families, preserving persisted stage indexes.
Existing review projections, targeted links, public reviewer history/Local Expert
and report evidence continue to consume approved-only source fields. Existing
projection and Local Expert review-write triggers process approved word changes.

POLICY / OUTCOMES
Candidate policy: openai-clean-or-human-v1; requested model omni-moderation-latest.
Unflagged valid results publish. Any broad/category flag is held for human review;
no score threshold, profanity blacklist, sentiment filter, permanent automatic
rejection, author restriction or Auth suspension. Invalid/unavailable/paused
screening keeps words private and reports that the rating saved. Ordinary
criticism, mild profanity, sarcasm and slang are not locally blocked. Fake clean
classifications cover these examples; real-provider false-positive assessment
remains a release prerequisite. Admin rejection applies only to proposed words,
erases their raw text immediately and preserves rating/older public words.
Both editors distinguish held/failed/rejected words from full save failure and
combine independent photo outcomes. Dish-detail preserves an unpublished draft;
current private drafts can be retrieved by their author when reopening Edit.
Create & Rate persists the draft on the server and returns normally after saving.

BOUNDS / FAILURE RECOVERY
200 UTF-16 headline units, 4,000 note units, 16,800 UTF-8 bytes maximum. Fixed HTTPS
POST /v1/moderations, 8-second wall timeout, 32-KiB response bound, no redirects,
strict single-result/13-category/type/score/model validation and no raw logs.
Six admitted new/version-retry screenings per author/minute. Provider allows two
concurrent requests per instance; callable candidate maxInstances=2/concurrency=2.
No automatic retries. Explicit same-text resubmission after 60 seconds can retry
up to TWO admitted attempts per version; private retention is never extended by
that retry. A 20-second attempt lease and unique attempt ID recover interrupted
work without accepting the old completion. Exhausted failures remain available
to human review until expiry. No read or projection trigger calls the provider.
Rate limiting does not apply the photo 1,000/month allowance to text.
